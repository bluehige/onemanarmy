## 1. 문서 목적

이 문서는 MVP 챕터 `객잔의 구검`에 필요한 그래픽 리소스를 제작자, 이미지 생성 세션, 2D 아티스트, 3D 아티스트, UI 디자이너에게 발주하기 위한 기준 문서다.

다음 사항을 고정한다.

- 리소스 ID와 파일명
- 제작 목적과 사용 장면
- 필수 구도·표정·상태
- 제작 우선순위
- 2D·3D·UI의 경계
- 원본과 런타임 출력 규격
- 수정 및 승인 기준
- 기존 UI 예시에서 유지할 것과 제거할 것

본 문서가 요구하지 않은 장비, 캐릭터, 배경, 메뉴, 검대는 MVP 자산 범위에 포함하지 않는다.

## 3. 공통 아트 방향

### 3.1 스타일

- 세미리얼 무협 누아르
- 먹색, 젖은 회색, 골회색, 흑철, 마른 혈색
- 인물은 선명하고 배경은 안개·비·연기로 깊이를 분리
- 일본 사무라이보다 중국·한국계 전통 무복과 도시 구조에 가까운 범동아시아 무협
- 검진은 선협식 마법광이 아니라 물리적인 검신, 금속 반사, 정렬, 간격으로 표현
- 이연의 움직임은 작고 검과 공간의 변화가 크다.

### 3.2 금지 스타일

- 카타나·하카마·사무라이 갑주 중심 실루엣
- 네온, 홀로그램, 사이버펑크
- 금색 갑옷과 황제형 장식
- 오색 오라와 거대한 에너지 용
- 판타지 MMORPG 장비 등급 광택
- 모든 검을 이연 뒤에 날개처럼 펼치는 반복 구도
- 코믹한 SD 비율

### 3.3 이미지 생성 시 고정 문장

> 성숙하고 절제된 36세의 해결사 이연, 낮게 묶은 검은 머리, 먹색 실용 무복, 왼손의 검은 쇠사슬, 허리 왼쪽의 장식 없는 무명검, 낮고 긴 흑철·그을린 목재 검관, 108검은 열두 개의 정돈된 검대로 분리, 무작위 검 폭풍이나 마법 오라 없이 기하학적으로 통제된 검진.

## 4. 원본 및 출력 규격

### 4.1 2D 배경

```yaml
master:
  size: 3840x2160
  color: RGB
  layers: PSD 또는 동등한 레이어 원본
runtime:
  primary: 2560x1440 PNG 또는 WebP 무손실/고품질
  minimum: 1920x1080
required_layers:
  - background_far
  - architecture
  - foreground
  - weather_fx_mask
  - light_fx_mask
  - damage_variant
```

배경은 최소 6% 확대와 좌우 4% 패닝을 해도 빈 영역이 생기지 않아야 한다.

### 4.2 캐릭터 스탠딩

```yaml
master_height: 3200px 이상
format: 투명 배경 PSD + PNG
anchor: 발바닥 또는 허리 기준 통일
variants:
  - body_pose
  - face
  - hand_prop
```

표정은 얼굴 전체를 새로 그리는 방식보다, 일관성을 유지할 수 있는 교체 레이어 구조를 권장한다.

### 4.3 이벤트 CG

```yaml
master: 3840x2160
safe_crop: 16:9와 21:9 모두 주요 피사체 보존
format: layered PSD + flattened PNG
text_safe_area:
  bottom: 화면 높이 28%
  top_right: 시네마틱 조작 UI 영역 비우기
```

### 4.4 UI

```yaml
source:
  - SVG 또는 벡터 원본
  - 9-slice PNG가 필요한 프레임은 원본 별도
reference_resolution: 1920x1080
scale_targets:
  - 1280x720
  - 1920x1080
  - 2560x1440
font_source: 라이선스 확인 가능한 프로젝트 폰트만 사용
```

### 4.5 3D

```yaml
exchange_format: glTF 2.0 또는 프로젝트 승인 포맷
scale: Godot 기준 1 unit = 1 meter
pivot:
  character: 발 중앙
  sword: 손잡이 중심축 또는 데이터 계약 위치
  sword_coffin: 바퀴 접지면 중심
materials:
  - base material 수 제한
  - 마스크 기반 젖음·피·그을음 변형
lod:
  - hero
  - mid
  - crowd 또는 multimesh
```

최종 폴리곤·텍스처 예산은 EXP-001 측정 뒤 승인한다. 현재는 형태와 동작 검증을 우선한다.

# 10. UI 그래픽 리소스

## 10.1 이전 UI 예시 반영 원칙

프로젝트 내부 UI 예시는 수묵·먹빛 톤과 기능 분류는 적합했지만, 한 화면에 목록·지도·상세·경고·버튼이 크게 병치되어 비주얼 노블보다 전략 RPG로 보였다.

CH01에서는 다음 구조로 축소한다.

- `Story`: 캐릭터와 배경 우선
- `Upper-Dantian`: 전술 선택 순간에만 전체 기능 노출
- `Confirm`: 별도 화면이 아니라 얇은 오버레이
- `Execution`: UI 거의 없음
- `Consequence`: 대표 결과 이미지 + 네 줄 이내

## 10.3 기본 대화 UI

### 레이아웃

- 화면 하단 26%.
- 좌우 여백 각각 6% 이상.
- 화자 명패는 패널 위에 떠 있는 작은 흑철·종이 결합 형태.
- 본문은 장식 붓글씨가 아니라 읽기 쉬운 한글 본문 서체.
- 우측 하단 보조 버튼은 본문 대비의 60~70%.

### 금지

- 대화창 외곽에 큰 검 장식.
- 이름표를 세로 붓글씨로 만들어 읽기 어렵게 함.
- 화면 상단에 장 제목, 목표, 인물 상태를 상시 표시.
- 캐릭터 얼굴을 가리는 높이.

## 10.4 상단전 UI

### MVP 전용 구조

검대 목록은 표시하지 않는다. 사용 검대가 무음검대 하나로 고정되어 있기 때문이다.

```text
전장 실제 이미지 70%
목표·검로 오버레이 13%
세 명령 카드와 결과 문장 17%
```

### 색 역할

- 선택·통제: 청백색
- 돌이킬 수 없는 살해: 마른 혈색 — CH01에서는 기본 미사용
- 위험·포기 목표: 탁한 황동
- 비활성: 저채도지만 읽을 수 있는 대비
- 민간인: 색 하나가 아니라 사람 문양과 텍스트 병용

### 금지

- 성공 확률 `+70%`.
- 검기 소모량.
- 검대 레벨과 강화 버튼.
- 12검대 카드 그리드.
- 화면에 목표 연결선이 너무 많아 실제 객잔 구조가 보이지 않는 상태.

## 10.5 결과 UI

### 필수 정보

1. 선택한 명령
2. 사람의 결과
3. 확보하거나 놓친 정보
4. 공간 피해
5. 검 회수 `9/9`

### 금지

- 명성 `+15`, 세력 `-5` 같은 점수.
- 세 결과를 `성공 / 부분 성공 / 실패`로 등급화.
- 도감·기록·획득물 패널을 한 화면에 모두 노출.
- 여러 반투명 상자가 인물 결과 이미지를 가림.

- [ ] 검관이 미래 병기함으로 보이지 않는다.
- [ ] 12잠금과 검갑 구조가 설명된다.
- [ ] 108검이 12개 덩어리로 읽힌다.
- [ ] 9검이 객잔에서 서로 다른 역할을 수행한다.
- [ ] 검 궤적이 VFX보다 검신 자체를 가리지 않는다.

## 환경

- [ ] 객잔 출구와 목표 위치가 전투 전·중·후 일치한다.
- [ ] 결과 분기별 손상과 인물 위치가 실제로 다르다.
- [ ] 비·안개·연기가 캐릭터와 검의 실루엣을 지우지 않는다.
- [ ] 일본식 거리·성문으로 오인될 장식이 과도하지 않다.

## UI

- [ ] 서사 화면에 상시 전술 HUD가 없다.
- [ ] 대화창이 캐릭터 얼굴과 검 움직임을 가리지 않는다.
- [ ] 상단전 시야는 세 명령의 결과와 대가를 즉시 설명한다.
- [ ] 검진 확정 화면이 전술 정보를 다시 전부 반복하지 않는다.
- [ ] 시네마틱에서는 UI가 10% 이하의 화면만 사용한다.
- [ ] 결과 화면은 대표 이미지와 네 줄 이내로 이해된다.
- [ ] 색을 구분하지 못해도 목표와 상태를 알 수 있다.

# 16. 발주 완료 조건

- 모든 P0 자산에 파일명, 원본, 출력본, 사용 Shot ID가 있다.
- 이연·검관·무음검대 기준 이미지가 `CANONICAL` 또는 명시적 승인 후보 상태다.
- 관천협 108검 원경에서 12검대의 분리가 읽힌다.
- 객잔 탑뷰와 실제 배경의 문·창·기둥 위치가 동일하다.
- 추적·수호·봉쇄 결과 이미지가 대사 없이 구분된다.
- UI는 비주얼 노블 화면과 전술 화면을 명확히 분리한다.
- 기존 UI 예시의 수묵·먹빛 정체성은 유지하되 전략 RPG형 상시 패널은 제거된다.
- 모든 생성·외주 자산에 출처와 수정 기록이 남는다.
- Godot 실렌더에서 720p와 1080p의 가독성을 확인하기 전 최종 승인하지 않는다.
