## 2. 이전 UI 디자인 예시 검토 결과

같은 프로젝트에서 제작했던 `S01 북문 계약`, `S02 상단전 시야`, `S03 검진 확정`, `S04 검진 집행`, `S05 결과` 예시의 기능 구조를 참고한다.

다만 기존 예시는 화면 구성이 아름다워도 전술 정보 패널이 크고 많아, 비주얼 노블보다 전략 RPG 또는 전술 게임으로 보이는 문제가 있었다.

### 2.1 유지할 요소

- 먹색·골회색·낡은 종이·탁한 적색의 제한된 색채
- 배경과 인물 일러스트가 화면의 주인공인 서사 화면
- 하단 25~30% 안에서 끝나는 대화창
- `상단전 시야`에서 목표, 검대, 직접 결과를 한 화면에 연결
- 검진 집행 때 UI가 접히거나 사라지는 전환
- 결과 화면에서 성공 점수보다 남은 사람·증거·피해를 보여 주는 구조

### 2.2 수정할 요소

| 기존 예시 문제 | CH01 적용 규칙 |
|---|---|
| 서사 화면에도 상단 제목판과 장식 프레임이 많음 | 장 제목은 진입 시 2~3초만 노출하고 사라짐 |
| 전술 목록·지도·상세 패널·하단 경고가 동시에 큼 | MVP에서는 선택지 3개만 노출하고 상세 설명은 선택 시 열림 |
| `검진 확정`이 지도와 결과표를 다시 반복 | 별도 전략 화면을 하나 더 만들지 않고, 화면 중앙의 얇은 확정 오버레이로 처리 |
| 시네마틱 중 목표와 문구가 화면을 계속 차지 | 목표 표시는 시작 2초와 상태 변화 순간에만 나타남 |
| 결과 화면에 여러 기록 상자가 겹침 | 대표 결과 이미지 1개 + 결과 3줄 + 검 회수 1줄로 제한 |
| 검대 관리 카드가 수집형 RPG처럼 보임 | CH01 본편에는 도감·강화 UI를 넣지 않음 |
| 수치형 성공률과 영향도 증감이 강조됨 | 확률과 명성 수치 대신 직접 결과 문장 사용 |

### 2.3 화면 우선순위

```text
서사 장면: 인물과 배경 70% 이상
상단전 시야: 전장 관계 55% 이상
검진 집행: 시네마틱 90% 이상
결과 장면: 물리적 후일담 이미지 60% 이상
```

## 3. 전역 연출 규칙

### 3.1 카메라 언어

- 이연의 명령은 손가락, 손목, 시선, 쇠사슬의 작은 움직임으로 보여 준다.
- 검진 결과는 원경과 3/4 시점으로 공간 관계를 먼저 보여 준다.
- 속도감을 위해 화면을 흔드는 대신, `정지 → 정렬 → 짧은 집행`의 대비를 사용한다.
- 적의 공포는 비명보다 자신이 이미 검로 안에 들어왔음을 깨닫는 시선으로 표현한다.
- 이연을 아래에서 과도하게 올려다보는 영웅 숏을 반복하지 않는다.
- 이연의 얼굴 클로즈업은 판단이 내려지는 순간에만 사용한다.

### 3.2 2D·3D 구분

| 화면 | 기본 방식 |
|---|---|
| 일상 대화·계약·심문 | 2D 배경 + 2D 스탠딩 + 제한적 패럴랙스 |
| 108검 콜드 오픈 | 3D 실시간 또는 3D 프리렌더 시네마틱 |
| 객잔 구검 자동 제압 | 3D 객잔 블로킹 + 2D 컷인 혼합 가능 |
| 상단전 시야 | 실제 객잔 3D 장면을 정지시킨 위에 UI 오버레이 |
| 결과별 집행 | 3D 짧은 시네마틱 |
| 후일담·북문 출발 | 2D 배경 + 스탠딩 또는 이벤트 CG |

### 3.3 대화창 규칙

- 기본 높이: 화면 높이의 26%.
- 화자 이름은 좌측 상단 작은 명패로 표시한다.
- `자동 / 로그 / 스킵 / 저장`은 대화창 우측 하단에 낮은 대비로 둔다.
- 대화가 없는 미장센 숏에서는 대화창을 완전히 숨긴다.
- 이벤트 CG 위에서는 반투명 검은 그라데이션만 사용하고 두꺼운 프레임을 피한다.
- 중요한 검 움직임이 하단에 있을 경우 대화창을 18% 높이로 축소한다.

### 3.4 상단전 시야 진입

```text
현실 음향 감쇠
→ 빗소리·불소리 저역만 남김
→ 화면 채도 감소
→ 인물과 위험의 윤곽선 표시
→ 검 9자루 위치 표시
→ 세 명령 카드 등장
```

진입 시간은 1.2~1.8초 안으로 제한한다.

### 3.5 시네마틱 UI

- 시작 시 좌측 상단에 현재 목적을 2초 표시한다.
- 우측 하단 `일시정지 / 요약 / 건너뛰기`는 마우스 이동 또는 키 입력 때만 나타난다.
- 성공 체크는 화면 중앙에 띄우지 않는다.
- 결과는 인물의 상태, 검의 위치, 불길, 열린 출구로 먼저 보여 준다.

## S00 선택 UI

화면 전체를 전략 보드로 바꾸지 않는다.

- 배경 시네마틱은 정지한다.
- 화면 하단 중앙에 선택지 두 개만 세로로 표시한다.
- 좌측에는 `지휘관`, 우측에는 `피난민 통로`에 얇은 윤곽을 표시한다.

```text
[지휘관을 생포한다]
정보를 확보한다. 피난민 통로 개방이 늦어진다.

[길만 연다]
피난민을 즉시 통과시킨다. 지휘관은 놓아준다.
```

# 10. S06 — 상단전 시야

```yaml
scene_id: SCN-MVP-060

```

## 10.1 화면 전환

1. 객잔 장면을 마지막 프레임에서 정지한다.
2. 주변 색이 먹색과 청회색으로 내려간다.
3. 불길, 인질, 도주자, 홍련에게 얇은 윤곽이 생긴다.
4. 무음검대 9검의 실제 위치가 화면에 표시된다.
5. 화면 하단에 `추적 / 수호 / 봉쇄` 세 명령이 나타난다.

## 10.2 수정된 레이아웃

기존 UI 예시처럼 왼쪽 검대 목록, 중앙 지도, 오른쪽 상세, 하단 버튼을 모두 크게 배치하지 않는다. CH01은 검대가 하나뿐이므로 다음처럼 축소한다.

```text
┌──────────────────────────────────────────────────────┐
│ 객잔 실제 장면 + 목표 윤곽                            │
│                                                      │
│  [도주자]              [인질]           [화재]       │
│           검 9자루의 현재 위치와 예상 검로           │
│                                                      │
├──────────────────────────────────────────────────────┤
│ [추적]          [수호]          [봉쇄]                │
│ 선택한 명령의 직접 결과 / 포기되는 목표              │
└──────────────────────────────────────────────────────┘
```

### 선택 카드

- 카드 높이: 화면의 14~17%.
- 역할 동사와 한 줄 결과만 기본 표시한다.
- 선택하면 카드가 확대되는 대신 전장 위 예상 검로가 바뀐다.
- `상세` 입력 시에만 설명 두 줄을 추가한다.

### 명령별 시각 프리뷰

| 명령 | 전장 표시 |
|---|---|
| 추적 | 창문 밖 북문 방향으로 3검 경로, 인질과 불길에 황동 경고 |
| 수호 | 인질범 손목과 불길에 6검 경로, 도주 경로가 점선으로 끊어짐 |
| 봉쇄 | 모든 출구를 잇는 9검 폐쇄 다각형, 화재 지연 경고 |

## 10.3 검진 확정

별도 `S03 검진 확정` 전술 화면을 다시 띄우지 않는다.

선택 완료 시 화면 중앙에 폭 42%의 얇은 오버레이만 표시한다.

```text
추적을 집행한다
도주자 생포 가능
객잔 내부 부상 위험

[배치로 돌아가기]       [집행]
```

- `집행` 선택 후 오버레이가 검관 판처럼 좌우로 접히며 사라진다.
- 붉은색은 처형 명령이 아니므로 사용하지 않는다.
- 확정 오버레이가 전장과 검로를 완전히 가리지 않게 한다.

## 18. 콘티 완료 수용 기준

- 첫 10분 안에 108검 전체 전개가 명확히 보인다.
- S00과 S05의 검 사용 규모와 성격이 확실히 다르다.
- 서사 화면에서는 배경과 캐릭터가 전체 화면의 70% 이상을 차지한다.
- 상단전 UI는 S06에서만 전체 기능으로 나타난다.
- 검진 확정 화면이 상단전 내용을 중복하지 않는다.
- 시네마틱 중 UI가 검과 인물을 가리지 않는다.
- 세 분기의 결과가 대사 없이도 배경과 포즈로 구분된다.
- 이연은 어느 장면에서도 통제 불능, 과부하, 공포 상태로 보이지 않는다.
- 검 108자루와 9자루의 움직임이 무작위 파티클이 아니라 역할과 공간으로 읽힌다.
- CH01 그래픽 발주서의 모든 P0 리소스가 각 Shot ID에 연결된다.
