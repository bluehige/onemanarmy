# VERTICAL SLICE PLAN

## 1. 목적

전체 게임의 축소판을 만드는 것이 아니라 다음 네 질문에 답한다.

1. 첫 10분 안에 이연과 108검이 구매 이유가 되는가.
2. 검대 배치가 짧고 명확하며 시네마틱 기대감을 만드는가.
3. 하드보일드 서사와 전술 판단이 서로 방해하지 않는가.
4. 첫 결과 뒤 다른 원칙의 선택을 보고 싶은가.

## 2. 수직 슬라이스 범위

### 플레이 분량

45~60분 목표. 실제 플레이로 재산정한다.

### 포함

- 프롤로그 `관천협의 108검`
- 백야성 입성
- `객잔의 구검`
- 북문 계약
- `불타는 시장의 오십사검`
- 계약 / 수호 분기
- 결과 2종
- 2회차 신규 선택 예고
- 기본 대화, 선택, 로그, 읽은 문장 스킵
- 상단전 시야
- 전술 배치
- 3D 시네마틱
- 결과 화면
- 자동 저장
- 최소 접근성 설정
- 개발 계측

### 제외

- 복수·군림 전체 루트
- 진상 루트
- 12검대 모두의 완성 자산
- 108명 검주 전체 기록
- 전체 음성
- 게임패드
- 최종 백야성 맵
- 상점·인벤토리·성장
- 모든 설정 화면
- 출시 패키징

## 3. 콘텐츠 범위

### 검대

수직 슬라이스에서 UI로 직접 사용하는 네 검대:

- 무음검대
- 반월검대
- 철성검대
- 용회검대

관천협 108검 전개에서는 나머지 검대가 시각적으로 등장할 수 있으나 플레이어가 역할을 직접 선택하지 않는다.

### 전투

#### BTL-001 관천협

- 목적: 108검 첫 상품
- 입력: 세 선택
- 전개: 9 → 36 → 72 → 108
- 결과: 피난민 보호, 지휘관 생포/처형 차이

#### BTL-002 객잔

- 목적: 9검 정밀 제압과 이연의 태도
- 입력: 대화 선택 1회
- 연출: 30~45초
- 결과: 정보 또는 공포

#### BTL-003 불타는 시장

- 목적: 실제 검대 배치
- 목표: 구조물 지지, 민간인 이송, 증인 추적
- 플레이어는 네 검대 중 세 개를 배치
- 계약/수호 분기 결과

## 4. 마일스톤

### M0 — 계약과 저장소 기준

산출물:

- Godot 4.6.3 프로젝트
- 폴더 구조
- source-of-truth
- 기본 headless boot
- Work Order와 baseline

완료:

- 빈 프로젝트가 editor/headless에서 오류 없이 부팅
- 기준 명령 기록
- 문서 경로와 런타임 경로 충돌 없음

### M1 — 108검 렌더러

산출물:

- 4개 실제 검대 + 8개 placeholder 검대
- 12×9 인스턴스
- 단계 전개·정렬·귀환
- debug ID와 count
- 성능 로그

완료:

- 108개 검 수 검사
- 9/36/72/108 단계
- 귀환 후 슬롯 중복 0
- 1080p 성능 캡처

### M2 — 관천협 시퀀스

산출물:

- graybox 협곡
- 이연 placeholder
- 검관
- 세 입력
- CameraDirector
- 화살·기병·지휘관 결과 variant

완료:

- 처음부터 끝까지 마우스·키보드 진행
- 선택과 장면 variant 일치
- EXP-001 내부 검수 가능

### M3 — Story Runtime

산출물:

- say, choice, flag, start_battle
- 대화창
- 로그
- 읽은 문장 스킵

완료:

- 공통 장면 fixture 완주
- 깨진 ID Validator
- 읽지 않은 문장 스킵 금지
- 저장 후 동일 장면 복구

### M4 — 상단전 UI와 BattleResolver

산출물:

- 목표 보드
- 검대 배치
- 예상 직접 결과
- 충돌 경고
- 집행
- 결과 화면

완료:

- BTL-003 세 목표 배치
- 검대 중복 차단
- 핵심 목표 미배치 경고
- 결과 인과 표시
- 720p/1080p E2

### M5 — 수직 슬라이스 콘텐츠

산출물:

- 45~60분 연결
- 배경·캐릭터 임시 또는 대표 품질 자산
- BGM·효과음
- 계약/수호 결과

완료:

- 처음부터 엔딩까지 중단 없이 진행
- 개발자 조작 없이 저장·로드
- 모든 선택에 결과 장면
- 임시 자산 표시와 최종 자산 구분

### M6 — 검증

산출물:

- E1 상태 캡처
- E2 실제 렌더
- E3 입력 완주
- E4 사용자 테스트
- KEEP/REDESIGN/KILL 판정

완료:

- Foundation과 Risk Register 갱신
- 전체 제작 여부 결정
- 실패를 성공으로 포장하지 않음

## 7. 플레이테스트 질문

설명하지 않고 관찰한다.

- 이연은 어떤 종류의 강자인가
- 108검은 어떻게 움직였다고 이해했는가
- 검대 선택 결과를 예상할 수 있었는가
- 가장 기억나는 장면은 무엇인가
- 어느 선택에서 멈췄는가
- 결과가 자기 선택 때문이라고 느꼈는가
- 다른 선택을 보고 싶은가
- 이연이 약하거나 답답하다고 느낀 순간이 있었는가
- 하드보일드하다고 느낀 근거는 무엇인가
- UI 때문에 이해가 어려웠던 부분은 무엇인가

## 8. 수직 슬라이스 통과 조건

- EXP-001 KEEP
- 핵심 UI Hygiene 결함 0
- 7명 중 5명 이상이 `한 사람의 군진` 판타지 인지
- 7명 중 5명 이상이 검대 선택과 결과의 인과 설명
- 7명 중 4명 이상이 다른 분기 재플레이 의향
- 이연이 약해 보였다는 반복 지적 없음
- 첫 10분 내 108검 상품성 확인
- 기준 PC에서 목표 성능
- 전투 장면 하나를 데이터 교체로 재사용할 수 있음
- 콘텐츠 제작 비용이 출시 범위로 확장 가능

## 9. 판정 뒤 행동

### KEEP

- GDD 수치와 기술 결정을 승인 상태로 갱신
- 공통부와 계약 루트부터 제작
- 12검대 아트·음향 생산 계약
- 전체 스토리 장면 목록 작성

### REDESIGN

원인을 하나로 분리한다.

- 연출
- UI
- 전술 규칙
- 템포
- 자산 스타일
- 성능

동시에 전부 뜯어고치지 않는다.

### KILL / 방향 전환

108검 연출은 유지하되 전술 배치를 축소한 선택형 시네마틱 VN을 검토한다. 이연을 약하게 하거나 일반 RPG 전투를 붙이는 방향으로 회피하지 않는다.
